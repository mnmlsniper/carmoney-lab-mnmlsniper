# Режимы Kilo: ask и code (задание 1.2.1)

Промпт: «В README не хватает раздела „Как проверить, что сервис жив“. Разберись по Makefile и docker-compose.yml, какие команды для этого есть, и добавь такой раздел в README.»

- **ask** — прочитал Makefile и docker-compose.yml, правильно нашёл `make up` / `make ps` / `make logs`, `/health` и healthcheck у db, предложил готовый текст раздела, но README не правил: сам сказал «в ask-режиме менять файлы не могу» и предложил переключиться на code. `git status` после него чистый.
- **code** — в новой сессии с тем же промптом сразу вписал раздел в README (после таблицы команд), разрешения на правку не спрашивал.
- Разница: ask только читает и отвечает, code меняет файлы. Без блока `permission` в `kilo.jsonc` code правит без подтверждения — поэтому права нужно настроить (1.3.2).
- Для разбора кода возьму **ask**: ответ тот же по качеству, а файлы гарантированно не тронет.

## ★ Четыре основных агента — что им можно (по описаниям в переключателе Kilo)

- **code** — агент по умолчанию: читает, правит файлы и запускает команды, насколько разрешает блок `permission` в `kilo.jsonc`.
- **ask** — только читает и отвечает/объясняет, кодовую базу не меняет.
- **plan** — может править только файлы плана, все остальные изменения в файловой системе запрещены.
- **debug** — диагностирует и чинит баги по методике отладки: читает, запускает, правит (как code, но с фокусом на поиске причины).
